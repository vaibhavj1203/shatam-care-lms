SHATAM CARE LMS - GUIDED DEMO (build it live, from scratch)
A ~20-minute walkthrough that shows someone how to USE the app by setting up a
real training scenario from an empty system and running a learner all the way to
a verified certificate. Teaching how to use it and showing the full feature set
are the same walk - so this one script does both.

   Prefer a 2-minute look without building anything? Run  python3 seed-demo.py
   from the frappe folder - it creates a ready course + accounts - then skip to
   ACT 4 and log in as demo.student@example.com / Kestrel-Bamboo-42.


THE STORY YOU'RE TELLING
   "A new batch of caregivers needs training. Watch me stand up a coordinator,
    a certificate approver, a course, and a learner - and take that learner
    from enrolment to a certificate an employer can verify online."

ONE NOTE BEFORE YOU START (so nobody is surprised)
   Students do NOT sign themselves up. A coordinator creates each caregiver's
   account and enrols them. That is by design today; self-signup is roadmap.
   If asked "how does a caregiver join?", that's the honest answer.

SET UP (the backend is usually already running)
   cd frappe && docker compose up -d
   cd shatam-care-web && npm run dev
   Everything is at http://localhost:3000. The ONLY login you need to begin:
       Administrator / admin
   Sign out between roles, or keep one role per private window so you can flip.

PEOPLE YOU'LL CREATE LIVE (pick any passwords; these are just examples)
   priya@example.com  / Coord-Demo-42    a full coordinator  (all five rights)
   ravi@example.com   / Appr-Demo-42     a certificate approver (one right)
   asha@example.com   / Learn-Demo-42    a caregiver (the learner)


====================================================================
 ACT 1 - SET UP YOUR TEAM AND THEIR PERMISSIONS   (as Administrator)
====================================================================
The point to land: "Evaluator" is not one fixed job. An admin hands each staff
member exactly the rights they need - nothing more.

1.  Log in as Administrator / admin. The dashboard shows every tool: Courses,
    Content, People, Groups, Review, Approvals.

2.  Click People. This is the roster. Every account carries a persona badge, and
    evaluators show which of the five rights they hold:
        Manage courses | Author content | Review content
        Approve certificates | Manage people

3.  Click "+ New person" -> persona EVALUATOR.
    Name: Priya Coordinator.  Email: priya@example.com.  Password: Coord-Demo-42.
    Tick ALL FIVE rights. Create.
    Say: "Priya helps me run everything - so she gets the full set."

4.  Click "+ New person" -> persona EVALUATOR.
    Name: Ravi Approver.  Email: ravi@example.com.  Password: Appr-Demo-42.
    Tick ONLY "Approve certificates". Create.
    Say: "Ravi only signs off certificates. That's the only tab he'll ever see -
          I'll prove that in a minute."

5.  Click "+ New person" -> persona STUDENT.
    Name: Asha Caregiver.  Email: asha@example.com.  Password: Learn-Demo-42.
    Create - a one-time password is shown; note it.
    Say: "This is how a caregiver 'signs up' - a coordinator creates them."

6.  On Ravi's row, click "Edit rights". Tick "Review content", save, then untick
    it and save again.
    Say: "Rights are editable any time - I can widen or narrow what someone does
          without recreating their account."

7.  Click Groups. Add a Student Group - title "Nashik — Coordinator Priya" and a
    region.
    Say: "Internal tags for reporting by region or field coordinator. Learners
          never see these."


====================================================================
 ACT 2 - BUILD A COURSE   (as Administrator)
====================================================================
8.  Click Courses -> "+ New course". Title: "Safe Patient Handling". Create.
    (An introduction is optional - a title alone is enough to start.)

9.  Open the course. Under Final Assessment, set pass mark 50 and Create. Add a
    question: "Safe lifting mainly protects which part of the body?" with options
    "Your back" (mark correct) and "Your hearing". Add question.

10. On the same page, under "Certificate Evaluators", search and add Ravi, then
    add Priya too.
    Say: "A course can have several approvers - so a whole team of coordinators
          shares the sign-off and nobody is a bottleneck."
    Under "Teachers", search and add Priya.
    Say: "Same for teaching - multiple authors per course. Adding a teacher also
          grants them the content-authoring role."

11. Click Content in the top bar -> open Safe Patient Handling -> "+ Add lesson".
    Chapter: "Module 1 — Foundations". Title: "Lifting a patient safely".
    YouTube: dQw4w9WgXcQ. Create. (The lesson starts as a Draft.)

12. >>> THE SIGNATURE AUTHORING TOOL <<<
    Open the lesson, let the video play a few seconds, and click
    "Pause here & add quiz checkpoint". The video pauses and a form appears
    pinned to that exact timestamp.
    Question: "When lifting a patient, what should you bend?"
    Options: "Your knees" (mark correct) and "Your back". Save checkpoint.
    Say: "That's the heart of the product - the teacher drops a question right
          onto the timeline, and the learner can't skip past it."
    (Add a second checkpoint later in the video if you want to show more than
     one; edit or delete one to show it's fully editable before anyone answers.)

13. MULTILINGUAL: on that checkpoint, open "Translations", choose Hindi from
    "Select a language...", type the question and options in Hindi (keep the
    correct one FIRST), and "Save translation".
    Say: "Shatam teaches across languages. One video, and the on-screen quiz
          appears in the learner's own language - we'll see Asha get it in Hindi."

14. Click "Submit for review", then go to Review in the top bar. The lesson is
    pending - click Approve.
    Say: "Nothing a teacher writes goes live until it's reviewed - a simple
          draft -> review -> publish safeguard."
    (To show the other side, click Reject instead; it returns to the teacher,
     editable, then re-submit and approve.)

15. Go to Courses -> open Safe Patient Handling -> Publish.
    Say: "Now it's live and enrollable."


====================================================================
 ACT 3 - ENROL THE CAREGIVER   (as Administrator)
====================================================================
16. Click People. On Asha's row, click "Enrol in course", pick Safe Patient
    Handling, Enrol.
    Say: "That's the enrolment flow - the coordinator puts the caregiver into
          the course. The caregiver just logs in and finds it waiting."


====================================================================
 ACT 4 - THE DELEGATED-STAFF EXPERIENCE   (quick, but it lands hard)
====================================================================
17. Sign out. Log in as ravi@example.com / Appr-Demo-42.
    The top bar shows ONLY "Approvals" - no Courses, Content, People, Review,
    nothing else.
    Say: "This is the whole promise of the permission model - Ravi sees exactly
          his one job and nothing he could break."

18. Sign out. Log in as priya@example.com / Coord-Demo-42.
    Now the bar shows Content, Courses, People, Groups, Review, Approvals - but
    NO learner tabs.
    Say: "Priya has the full staff toolkit. Notice staff are never shown the
          learner's course/certificate tabs - the two worlds stay separate."


====================================================================
 ACT 5 - WHAT THE CAREGIVER EXPERIENCES   (log in as Asha)
====================================================================
19. Sign out. Log in as asha@example.com / Learn-Demo-42.
    She sees only "Courses" and "Certificates" - a clean, low-clutter view.

20. (Optional) Open a course she is NOT enrolled in. She can preview the outline
    with an "Enroll" button - not a locked error - but can't open lessons until
    enrolled.

21. Open Safe Patient Handling. Set the Language dropdown to Hindi (it saves
    immediately).
    Say: "Asha picks her language once."

22. >>> THE MOMENT THAT SELLS IT <<<
    Open "Lifting a patient safely". Let the video reach the checkpoint.
    The video PAUSES and the question appears over it - in HINDI, because that's
    Asha's language. She cannot continue until she answers.
    Choose the FIRST option (the "knees" answer) and Submit -> "Correct!" ->
    Continue watching, and the video resumes.
    Say: "She just proved she was watching - in her own language. Answers are
          matched by position, so the grading is language-independent."

23. Reload and play from the start. The question does NOT interrupt again.
    Say: "First watch only - revising a lesson later is never punished."

24. Let the video finish. It marks the lesson complete, then go back and click
    "Take assessment". Answer it (the back is what safe lifting protects), submit
    -> "You passed!" and a note that the certificate is awaiting approval.
    Say: "Finishing the videos isn't enough - a human still has to approve
          before a certificate is issued."

25. Click Asha's name (top right) -> My Account. Change her password (wrong
    current password is refused; the correct one works).
    Say: "Learners manage their own password - no admin needed for that."


====================================================================
 ACT 6 - APPROVAL AND A VERIFIABLE CERTIFICATE
====================================================================
26. Sign out. Log in as priya@example.com -> Approvals. Asha is listed as
    eligible and pending. Leave this open.

27. In a second window, log in as ravi@example.com -> Approvals.
    Asha is pending HERE too.
    Say: "The queue is shared - every approver sees the same list, not a split."

28. As Ravi, click "Approve & issue certificate". The row disappears. Now refresh
    Priya's Approvals window - Asha is gone there as well.
    Say: "The instant one coordinator approves, it clears from everyone else's
          queue. No double-issue, no two people working the same learner."

29. Sign out. Log in as asha@example.com -> Certificates.
    There's a certificate with an ID like SCF-2026-000001.

30. >>> VERIFIABLE BY ANYONE <<<
    Click "Verification page" - "Valid Certificate" with name, course and date.
    Copy that URL into a private/logged-out window: it STILL resolves.
    Say: "An employer confirms a caregiver's credential with no account and no
          login. Every certificate also carries a QR code to this page."

31. Click "Download PDF" to show the printable certificate.


====================================================================
 YOU'VE NOW SHOWN THE WHOLE PRODUCT
====================================================================
   Permissions & delegation (Acts 1, 4) . groups (Act 1) . course + assessment
   authoring (Act 2) . multiple teachers/evaluators (Act 2) . in-video
   checkpoints + the authoring scrubber (Act 2) . multilingual quiz text
   (Acts 2, 5) . draft->review->publish (Act 2) . admin enrolment (Act 3) .
   the learner flow with first-watch enforcement (Act 5) . self-service password
   (Act 5) . shared approval queue (Act 6) . public QR certificate + PDF (Act 6).

BE UPFRONT IF ASKED (not bugs - deliberate v1 scope)
   - No self-service signup; a coordinator creates each account.
   - Branding is placeholder - green, no logo, stock certificate design.
   - Final-assessment questions can't yet be translated from the UI (the
     in-video checkpoints can, as shown in Act 2/5).

IF SOMETHING MISBEHAVES MID-DEMO
   Have a backup private window logged in as Administrator.
   Backend logs: docker compose logs --tail 100 frappe

WHEN DONE
   docker compose stop     (keeps everything; "start" brings it back in seconds)
   Do NOT use "docker compose down" - it discards the running setup.
